# Packwright 0.3.2

Packwright 0.3.2 closes the gap between projecting Codex hooks and proving that
the current hooks actually ran. It also makes migration and reconcile receipts
more precise without turning expected runtime-review steps into structural
doctor failures.

## Install

```bash
python -m pip install packwright==0.3.2
```

## Codex activation receipts

Installed Codex hook commands now use the target's absolute runner path, so
starting Codex from a non-Git subdirectory does not redirect the hook to the
wrong working directory. Both add-context handlers set
`additionalContextLimit: 0`; Packwright's per-automation byte budgets remain
the hard producer limits.

Codex records trust against the current hook hash. After install or reconcile:

1. run `/hooks` in Codex CLI and trust the Packwright `SessionStart` and
   `UserPromptSubmit` hooks;
2. start a new session in the installed target and submit one prompt; and
3. run:

```bash
packwright verify-activation <target> --adapter codex
packwright doctor <target>
```

The generated runner records successful event execution locally after flushing
its output. `verify-activation` accepts only evidence matching the current
target and managed hook digest, then writes a durable local receipt. Editing or
reconciling the managed hook fragment changes that digest and returns readiness
to attention-required until the new hooks run and are verified.

## Receipt and state-safety corrections

- Migrate/reconcile `ok` now means the requested operation applied with its
  integrity checks intact. Installed checker results are reported separately as
  `installed_score_passed`; reconcile also reports `doctor_ok`.
- Reconcile dry-run includes its receipt, relocation baseline, and full managed
  JSON normalization in the planned write set. A moved target cannot be
  silently re-anchored.
- An empty destination combined with active Emotion Engine projection and
  `--no-emotion-state` explicitly reports that source continuity is excluded
  and fresh state will initialize with `trust_anchor=0.1`.
- Readiness recognizes declared Emotion Engine MCP configuration while keeping
  live client availability and approval honestly unverified.

## Canonical and migration fixes included

This release also makes canonical `operating/principles.md` the single source
for entry-file Working Rules, reports destination-only portable-state removals
before forced migration, accepts populated session indexes as live state, keeps
truncation markers within producer budgets, and scores reconcile against the
installed live tree.

## Verification

The source suite contains 130 tests, including live generated-runner execution,
digest invalidation, non-Git subdirectory startup, exact reconcile dry-run/apply
write-set comparison, all 12 directed adapter migrations, and state-reset
reporting. The release gate additionally checks zero-network behavior, public
tree hygiene, isolated package builds, and wheel/sdist installs across the
supported Python matrix.

## Compatibility

Packwright 0.3.2 remains local-only and requires Python 3.9 or newer. Codex
targets need one new hook review after upgrading because the managed hook
configuration changed. Claude Code, Cursor, and Pi activation behavior is
unchanged.
