# Packwright 0.3.4

Packwright 0.3.4 makes the optional Emotion Engine integration safe for the
v2.0.0-rc.4 state, identity, capability, bounded-session, and mode contracts.
Updating the runtime no longer implies that an existing process or state is active.

## Install

```bash
python -m pip install packwright==0.3.4
```

## One writer cohort

Packwright now pins Emotion Engine `v2.0.0-rc.4` and projects the helper, MCP
server, registration helper, schema, template, adapter-native skill, shell/MCP
wrappers, and lifecycle bridge as one versioned cohort. A completed projection
receipt records every managed file digest. `doctor` fails closed on an
interrupted refresh, mixed version/schema/capability metadata, identity drift,
or any writer that no longer matches that receipt.

The project shell wrapper now forwards through a fixed-state gateway instead
of calling the helper directly. The gateway shares Packwright's target lock,
rejects installer-owned identity/migration/upgrade commands, and commits
pause/resume state together with manifest mode and artifact-lock metadata.

Runtime and state are release-generation scoped. A v1/rc.3 MCP process that
was already running keeps its old state path and cannot rewrite the rc.4 v3
packet. Every refresh publishes a new projection nonce; the cohort-aware MCP
launcher refuses further requests from an older nonce and writes a live
activation receipt only after the pinned server answers `initialize` with the
expected version. Restart the client after refresh before migration.
The launcher starts the engine with locked-state and managed-runtime controls,
rejects request-level state path overrides before forwarding, and atomically
marks the manifest's MCP/activation records live after a successful handshake.

Packwright no longer creates or directly patches Emotion Engine JSON. Fresh v3
state is initialized and bound by the engine helper. Existing v2 or v3 state is
preserved byte-for-byte by install, refresh, force, and doctor repair.

## Explicit state migration and capability upgrade

After refreshing an older target, review the no-write plan:

```bash
packwright migrate-emotion-state --target-dir <target>
```

The plan shows the stable identity derived from the installed character slug.
Placeholder slugs such as `character` are never accepted implicitly; provide
both `--character-id` and `--relationship-id` after confirming ownership.
Apply only after review:

```bash
packwright migrate-emotion-state --target-dir <target> --yes
```

Apply writes a timestamped backup under `.emotion-engine/backups/`, delegates
the migration to Emotion Engine, then requires both `activation_check` and
`audit_state` to pass. Until that succeeds, the manifest reports installed and
configured but not active or verified.

The apply path records every phase in a persistent transaction journal. Any
helper, activation, audit, manifest, or artifact-lock exception restores the
pre-migration state, manifest, and lock. A later invocation automatically
recovers an incomplete journal left by process interruption.

The same reviewed command upgrades older v3 packets that lack a newly required
capability. Packwright preserves the packet byte-for-byte during refresh,
previews the capability upgrade, writes a separate v3 backup on apply, and
publishes the upgraded state only after the normal activation and audit gates.

## Native Codex lifecycle

Codex targets receive a managed `SessionStart` bridge only when the installed
state advertises `session_idempotency/v1`. The bridge preserves the host-native
event and session id, treats replayed startup/resume/clear/compact events for
one session as no-ops, and never invents a close event. A new native session id
causes the previous active session to close immediately before the new start.
Paused, legacy, unbound, capability-incomplete, or identity-mismatched state is
not written.

Claude Code and Cursor keep their project-local MCP projections but do not
receive a fabricated lifecycle mapping until Packwright can verify equivalent
native session identity behavior.

## Verification

The release suite covers fresh bound v3 initialization, byte-identical v2
refresh, dry-run and applied migration with two recovery copies, activation and
state audit gates, mixed-writer diagnosis, paused no-ops, lifecycle replay, and
deferred close. A separate integration smoke uses the real Emotion Engine
`v2.0.0-rc.4` commit for fresh install, old-process isolation, concurrent
refresh, migration rollback, audit, mode synchronization, and lifecycle checks.

## Compatibility

Packwright 0.3.4 remains local-only and requires Python 3.9 or newer. Emotion
Engine v1.0.0 sources are intentionally rejected by this release because they
do not implement the required v3 identity and session idempotency contracts.
Pi Core remains an inert-snapshot destination for Emotion Engine state.
