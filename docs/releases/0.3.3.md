# Packwright 0.3.3

Packwright 0.3.3 closes the remaining gap between executing a Codex hook and
proving that its complete managed context reached the model. Activation
receipts now verify delivery in the recorded Codex transcript instead of
accepting runner execution alone.

## Install

```bash
python -m pip install packwright==0.3.3
```

## Transcript-verified Codex activation

Codex `SessionStart` and `UserPromptSubmit` runners now emit the explicit
`hookSpecificOutput.additionalContext` JSON envelope. Their handlers use
`additionalContextLimit: 100000`, while Packwright rejects compiled per-event
budgets above a conservative 96000-byte transport ceiling.

Activation stamps and receipts use schema v2. `packwright verify-activation`
now requires all of the following:

- the expected events executed from real Codex hook input;
- the exact complete context appears as a `developer` message in the matching
  Codex transcript;
- the evidence matches the installed target and current managed hook digest;
- the generated runner digest still matches the installed runner; and
- every required canonical automation is present.

Manual runner execution and execution-only v1 evidence fail closed. Editing or
reconciling either the managed hook fragment or runner invalidates the old
receipt and returns runtime activation to attention-required.

## Upgrade steps for Codex targets

The published 0.3.2 handler used `additionalContextLimit: 0`. After upgrading
an ordinary 0.3.2 target, reconcile changes the managed hook hash, so review and
trust both Packwright hooks again with `/hooks`. Then start a new session,
submit one prompt, and run:

```bash
packwright verify-activation <target> --adapter codex
packwright doctor <target>
```

A target whose handler was already patched to the byte-identical 0.3.3 hook
definition keeps its persisted hook trust, but still needs a new session and
v2 receipt because the runner digest changed.

## Verification

The source and sdist suites contain 131 tests. The full release gate also
checks zero-network behavior, public-tree hygiene, wheel/sdist metadata,
isolated installs, all four adapter build/install/doctor/score paths, and
Cursor/Pi migration smoke tests.

Before release, a fresh `work` assistant was built and installed from public
`main`, then exercised through Codex CLI 0.146.0-alpha.9.2. Both managed events
ran, the model received the complete context, activation v2 returned
`delivery_verified: true`, doctor reported no issues with runtime activation
`passed`, and structural score remained 100.0.

## Compatibility

Packwright 0.3.3 remains local-only and requires Python 3.9 or newer. Claude
Code and Cursor output protocols are unchanged. Pi Core trust and lifecycle
extension boundaries are unchanged.
